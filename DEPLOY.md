# AEON OS — Production Deployment

AEON OS deploys as a **single full-stack unit on Oracle Cloud**: frontend,
Flask kernel, Postgres database, and TLS termination all run on one Compute
VM via Docker Compose.

```
Oracle Cloud VM (Ubuntu, Ampere A1)
┌────────────────────────────────────────────────────────────┐
│  Caddy :80/:443 ── auto-HTTPS ─┬─▶ web    (Next.js :3000)  │
│                                └─▶ backend (Flask  :5000)   │
│                                     └─▶ postgres (:5432)    │
│  data persists in Docker volumes (pgdata, backend_state)   │
└────────────────────────────────────────────────────────────┘
```

## Quick start

```bash
ssh ubuntu@<VM_PUBLIC_IP>
sh -c "$(wget -qO- https://raw.githubusercontent.com/beatznlg/aeon/main/scripts/deploy-oracle.sh)"
```

The script installs Docker, generates strong secrets into `/opt/aeon/.env`,
and starts the whole stack. Edit `/opt/aeon/.env` (domain, admin seed, LLM
keys), then:

```bash
cd /opt/aeon
docker compose -f docker-compose.oci.yml up -d
```

**Full step-by-step instructions:** see [DEPLOY_ORACLE.md](DEPLOY_ORACLE.md).

## Required environment variables

| Variable | Required | Purpose |
|---|---|---|
| `POSTGRES_PASSWORD` | ✅ | Database password (auto-generated by setup script) |
| `AUTH_SECRET` | ✅ | Auth.js session signing |
| `AEON_JWT_SECRET` | ✅ | Kernel JWT signing |
| `AEON_MASTER_KMS_KEY` | recommended | Encryption-at-rest master key |
| `AEON_DOMAIN` | for HTTPS | Your DNS name; empty = HTTP only |
| `AEON_ADMIN_EMAIL` / `AEON_ADMIN_PASSWORD` | first boot | Admin user seed |
| `AEON_LLM_PROVIDER` | no | `stub`, `openai`, `anthropic`, … (default `stub`) |
| `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` | if LLM ≠ stub | Provider keys |

Supabase variables are optional — the platform falls back to its local
Postgres when they are unset.

## Verify

```bash
curl http://localhost/health                    # {"ok": true, ...}
python scripts/healthcheck.py https://<your-domain>/api/health
```

## Updating

```bash
sh scripts/deploy-oracle.sh        # pulls main, rebuilds, restarts; data survives
```

## Monitoring & CI/CD

- Prometheus metrics: `/metrics` · health: `/health` · readiness: `/ready`
- GitHub Actions workflows on push/tag:
  - `docker-ci.yml` — lint, typecheck, Docker image build
  - `docker-release.yml` — multi-arch images pushed to GHCR on tags
  - `quality-gate.yml` — pytest, ruff, Bandit, pip-audit

Interactive API docs live at `https://<your-domain>/docs`
(OpenAPI spec at `/openapi.json`).
